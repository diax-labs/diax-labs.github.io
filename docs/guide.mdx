# Getting Started (/docs/guide)





Start from the job [#start-from-the-job]

DiaX is a DOM-native diagram runtime. Your content remains real HTML and framework components;
DiaX supplies automatic placement or connection geometry at an explicit ownership seam.

<Callout type="info">
  **DiaX connects real DOM. You explicitly choose who owns layout.**
</Callout>

| What you already have                                   | Start with               | Layout owner                                                                |
| ------------------------------------------------------- | ------------------------ | --------------------------------------------------------------------------- |
| Nodes and relations                                     | **Diagram**              | DiaX places nodes and routes edges                                          |
| JSX, Tailwind or semantic HTML with the right placement | **Connect DOM**          | Your CSS places content; DiaX connects it                                   |
| Mermaid source                                          | **Mermaid Import**       | Mermaid supplies topology; DiaX renders the supported subset as DOM         |
| Markdown or MDX fences in a build pipeline              | **MDX Integration**      | Remark transforms supported source and reports invalid fences through VFile |
| AI-generated content                                    | **Agent-first Workflow** | Choose Diagram JSON or reviewed Connect JSX, then validate the built result |
| A topology but no visual design system                  | **UI Primitives**        | DiaX places styled DOM presentation primitives                              |

Fastest path: Diagram [#fastest-path-diagram]

Use Diagram when topology is already data and DiaX should place it. Pick your framework, select its
package, and pass `nodes` plus `relations`. During the unpublished preview, the package panel gives
you the repository workflow instead of a registry command that cannot succeed.

The framework adapter hides parsing, validation, layout, DOM measurement and edge rendering behind
one interface. Move to hooks, stores or Core primitives only when your renderer genuinely needs that
control.

Already own the layout? [#already-own-the-layout]

Do not rebuild a report or dashboard as diagram nodes. Keep the authored DOM and use the isolated
React Connect entry to mark the exact endpoints:

```tsx contract
import { ConnectionSurface, connectionTarget } from '@diax/react/connect';

export function DecisionReport() {
  return (
    <ConnectionSurface relations={[{ from: 'claim', to: 'evidence' }]}>
      <article {...connectionTarget('claim')}>Conversion improved.</article>
      <aside {...connectionTarget('evidence')}>Experiment results</aside>
    </ConnectionSurface>
  );
}
```

[Read the Connect guide →](/docs/react/connect)

Generating with AI? [#generating-with-ai]

Use validated JSON for untrusted runtime output. Use JSX or MDX only in a trusted, reviewed code
workflow. The Agent-first guide connects classification, validation, built preview, review and
delivery without adding a new runtime mode.

[Follow the Agent-first workflow →](/docs/guide/agent-workflow)
