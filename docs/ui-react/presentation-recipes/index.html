Release Status & Setup

Keep presentation in JSX

Promotion reviews, architecture briefs, blog figures and AI-generated explanations rarely consist of one graph. They combine claims, metrics, code, evidence, decisions and a few relationships. Keep that composition as semantic HTML and CSS; use Connect only for the relations that materially improve the story.

These complete compositions remain copy-owned recipes. Their recurring inner roles can now use @diax/ui-react/presentation Presentation Nodes, while report-specific wording, grids and system boundaries stay in your application.

The signature is not a generic dashboard card. It is an evidence ledger: every visual block has one role, visible provenance language and a reviewable relationship to the next decision. The authored DOM still controls the reading order when edges are absent, loading or suppressed by print tooling.

System boundary brief

Architecture explanations have a different job: show where ownership changes without flattening every layer, actor and panel into one graph model.

The green enclosure is an ordinary semantic <section>, not a DiaX Group. Its heading, rail, internal grid and responsive behavior belong to authored HTML/CSS. Only the four cards that act as relation endpoints use connectionTarget(). This keeps “system boundary” in the application's domain vocabulary without adding a second containment or layout model to Connect.

For an AI author, state that distinction explicitly:

Timeline: chronology is an ordered list

Use an <ol> when the reader must understand order even if CSS, color or connectors disappear. StageNode owns each phase's visible status and owner; the list owns chronology. Dates, milestones, duration scales and dependency graphs vary too much across roadmaps, migrations and incident reviews to justify a public Timeline component today.

Comparison: preserve the two-dimensional question

Comparisons are not graphs by default. Use <table>, column and row scopes, a caption, and a focused internal scroll region on narrow screens. Highlighting a recommended column is useful decoration; the visible “Recommended” text and following DecisionNode carry the conclusion. Before/after stories with only two narrative panels may use two articles instead, but should not pretend to be a matrix.

Swimlane: authored ownership, measured handoffs

A lane is a responsibility boundary, not another DiaX topology object. Keep it as a named <section> and place real DOM tasks inside it. Connect the few handoffs that help the reader follow the response. At narrow widths the sections stack in source order, preserving Security → Platform → Release without requiring mobile coordinates or alternate relations.

Deleting the application-owned composition removes its report-specific hierarchy. Deleting Connect would push DOM measurement, observers, anchors, SVG layers and cleanup into every report. The recurring metric, evidence, risk, actor, stage, system and store roles have graduated into Presentation Nodes; the evidence-ledger and system-boundary compositions deliberately have not.

Semantic structure first

Use native elements before styling hooks:

  • <figure> and <figcaption> describe one exportable visual;
  • <article> owns a claim that can stand alone;
  • <dl>, <dt> and <dd> preserve metric name/value semantics;
  • <aside> contains the resulting recommendation or constraint;
  • <section aria-labelledby> gives an authored system boundary a durable accessible name;
  • connectionTarget() marks the exact existing element DiaX should measure.

Do not turn every caption, badge or metric into a graph node. A target is a measured endpoint, not a new content taxonomy.

Vendor identity decorates a semantic role

A provider logo answers whose product is this? It does not answer what does this node do? Choose ActorNode, SystemNode, ArtifactNode or another semantic role first. Use NodeCard only when the application has a real role that does not match one of those components; then add an application-owned mark through icon. A person's or team's approved portrait can use ActorNode.avatar under the same policy.

The visible title remains the accessible identity. Treat a familiar mark as decoration, hide it from the accessibility tree, and never make a reader infer “GitHub”, “AWS” or another vendor from color or shape alone. The application—not DiaX—owns the icon import, allowlist, source, license/trademark review and bundle cost.

The generated definition selects only the allowlisted sourceHost ID. It cannot provide an import, SVG payload or logo URL. When the ID is absent or unknown, the renderer keeps the semantic fallback and omits the mark; it does not search the network or guess a visually similar vendor.

Do not add brand to the shared graph schema. Vendor identity is optional presentation metadata in trusted application code. Topology, role, visible name and provenance must remain meaningful when every logo is removed.

Responsive and print contract

Use auto anchors when the same authored surface changes from columns to rows. Fixed left/right anchors encode desktop geometry and usually become wrong at narrow widths. Budget the connector track from the largest expected label. These recipes keep 48px between stacked cards and 80–96px between columns, leaving at least 8px around their current labels.

@diax/ui-react/styles.css already resets DiagramFrame, presentation nodes and badges to a high-contrast paper palette. The recipe still owns page size, authored tables and whether interactive Connect hit areas or application actions belong in the exported artifact. Browser automation checks computed print styles and overflow. A selected product-brief corpus additionally generates four bounded A4 pages, but it still cannot prove installed brand fonts or a physical print.

Test at the actual destination ratio. A 16:9 presentation, an article column and an A4/PDF page have different line lengths and failure modes; aspect-ratio is a recipe constraint, not a Core option.

When a recipe graduates into UI React

A presentation role may become a public primitive only after it:

  1. appears in at least two distinct real diagram families;
  2. hides repeated accessibility, theme or interaction behavior—not only class names;
  3. remains useful inside Diagram, Connect and ordinary DOM;
  4. has forced-colors, keyboard, responsive and visual contracts;
  5. does not introduce a second topology or layout model.

Until then, copy-owned JSX gives teams and AI agents more expressive freedom with less compatibility surface.

The first graduation happened after the promotion-review corpus showed repeated implementations across architecture, security, i18n and rollout diagrams. See Presentation Nodes for the resulting small interface and the roles that remain application-owned.
