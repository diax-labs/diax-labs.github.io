Question-First Recipe

Who sends each review message, and in what exact order?

Use authored message rows and one measured endpoint per sender and receiver. Keep an ordered transcript in the same DOM and make it primary on narrow screens.

Use this shape when

  • Explain a request and response protocol where exact message order matters
  • Keep a reviewable transcript while showing responsibility across people, agents and systems

Choose another shape when

Avoid a sequence composition when topology, branching or containment matters more than chronological message order.

Facts the author or agent must know first

  1. The artifact or evidence carried by each important message
  2. The exact message order
  3. The final delivery acknowledgement
  4. The participant responsible for every send and receive
  5. Which messages are requests versus returns or receipts
Copy-ready agent prompts

English

Create a sequence-style protocol with @diax/react/connect. Use semantic participant headings, one authored row per ordered message, stable message IDs, solid requests, dashed returns, and an accessible transcript. Do not add y coordinates, lifeline ports, messageAt or a sequence mode.

中文

使用 @diax/react/connect 创建序列协议。使用语义化参与者标题、每条有序消息一个 authored row、稳定消息 ID、实线请求、虚线返回和可访问 transcript。不要添加 y 坐标、lifeline port、messageAt 或 sequence mode。
